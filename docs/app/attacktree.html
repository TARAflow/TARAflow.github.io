Attack Tree

Model AND/OR attack trees for high-impact assets. Assess probability and feasibility per leaf node, and link tree paths back to the threat table.

01

Attack Tree Workflow

  • Derive attack goals from high-impact assets (Variant B) or high-risk threats (Variant A, Phase 5A)
  • Model AND/OR trees: AND-nodes require all child conditions, OR-nodes require any one
  • Assess probability and feasibility per leaf — escalates to parent nodes
  • Link attack tree leaves to STRIDE threats in the threat table for traceability
  • Validate Won't-fix decisions: if attack tree shows a viable path, reconsider
02

Integration with STRIDE

The feedback loop between STRIDE and Attack Trees checks: all attack paths covered by at least one STRIDE threat? Missing STRIDE categories? Inconsistent likelihood estimates between tree leaves and threat scores? Iterate Phase 3 until the cross-check is clean.
