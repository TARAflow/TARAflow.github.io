Hazard Identification

An optional safety-analysis tab, alongside the security workflow: model each hazard as a Bowtie — contributing causes on the left, the hazard with its gate in the middle, endangered safety goals on the right — and triage which hazards a cyberattack can actually reach.

01

Enabling the tab

  • Off by default — a project only gets a Hazard tab once marked safety-relevant via the switch in the Overview tab (below the Criticality switch)
  • Existing projects are unaffected; no migration required
  • When enabled, Hazard also joins the Overview progress bar alongside the other phases
02

The Bowtie model

Each hazard item is a Bowtie: assets that contribute to it on the left, the hazard with a combination gate in the middle, and safety goals it endangers on the right.

  • Causes — contributing assets, each rated direct or indirect and (optionally) by hazard distance
  • Gate — combinationType: ANY (OR — a single cause is enough) or ALL (AND — causes must combine); only meaningful once a hazard has two or more causes
  • Targets — endangered safety goals, each rated on a severity scale specific to its target type (human / environment / infrastructure)
  • Assets can be created inline from the Bowtie editor without leaving the dialog
03

Review workflow

  • A master-detail review workspace, not a plain edit dialog: a sidebar lists every hazard with its review status and completeness, the detail pane holds the decision and the Bowtie
  • Every hazard is first triaged on one question — is this reachable by a cyberattack? — answered as in scope, out of scope (with a required reason), or unknown
  • Only in-scope hazards need a Bowtie modeled; out-of-scope hazards stay in the safety record but are excluded from threat derivation, never deleted
  • Commit-on-close: there is no separate Save button — closing the dialog (OK, Escape, or clicking outside) commits the draft
04

Import

  • Bring in hazards from an existing safety analysis (CSV, Excel/ODS, or a TARAflow JSON export) via a profile-based importer with an interactive column-mapping dialog
  • Affected-persons data is bridged into deduplicated human assets with structured, per-role severity — not collapsed into one flat rating
  • Provenance from the source file (extra columns that don't map to a known field) is retained on the imported item
