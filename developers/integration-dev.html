Integrations

Ticket adapter pattern for Jira, ADO, GitHub Issues, and future systems.

01

ITicketAdapter

  • Interface: createTicket(mitigation) → TicketRef, getTicketStatus(ref) → Status, updateTicket(ref, patch)
  • BaseTicketAdapter: shared credential resolution via keytar, error handling, retry
  • JiraAdapter, ADOAdapter, GitHubAdapter — concrete implementations
  • Polarion, GitLab adapters: planned via same interface
  • No plaintext secrets — credentials stored in OS keychain via keytar
02

RichText Ticket Cards

  • Ticket body is generated from a template: threat description, risk level, mitigation text, verification criteria, DFD element reference, norm references
  • POST body assembled in the adapter — Jira uses Atlassian Document Format (ADF), ADO uses HTML, GitHub uses Markdown
  • Ticket ID and URL stored back on MitigationDraft.ticketRef for status sync
