DFD Engine

The DFD engine bridges draw.io XML to the typed graph model used by the threat generator.

01

DFDGraphReference

  • elementsById: Map<string, DFDElementReference> — all elements by ID
  • connectionsById: Map<string, DFDConnectionReference> — all DataFlows by ID
  • effectiveElementTrustBoundary: Map<string, string> — innermost TB per element (prevents duplicates in nested TBs)
  • elementPhysicalBoundaries, elementChipBoundaries — PB/CB membership maps
  • chipBoundaryElements, physicalBoundaryElements — reverse maps
02

toReferenceGraph()

  • Parses draw.io XML via the bridge IPC channel
  • Resolves parent IDs to determine TB/PB/CB membership geometrically
  • Maps element.properties from draw.io custom properties to typed DFDElementReference.properties
  • Computes effectiveElementTrustBoundary using the innermost-TB rule
  • Called in workspace-layout.tsx; result stored as project.dfdGraph
03

Asset Graph (features/dfd/asset-graph)

  • buildAssetGraph: pure preparation of nodes, edges, stubs and counts for the layer and focus view
  • layoutAssetGraph: d3-force with one lane per layer and a fixed-seed random source — deterministic; known positions are fixed, only new nodes move
  • Positions are view state: kept per session and in browser storage per project id, never in the project file
  • Edit mode writes nothing itself: asset links go through A2AOpsContext → commitA2AOps → relations service; assets, asset properties and element relations through the DFD tab's existing callbacks
  • Undo / redo names links by (source, target, type), not by id — a restored link gets a new id and is still found
04

Leveled DFDs (features/dfd/services/leveled)

  • Each draw.io page is parsed separately; the page tree and the identity links (definition ↔ context copy) live in dfd.pages of the project, not as XML attributes
  • Effective model (effective-model.ts): the leaves of the decomposition and, per logical flow, one resolved pair of endpoints stitched from all its occurrences — the deepest endpoint on one containment chain wins; otherwise the flow falls back to the parent level, never "pick one". Derived on every load, never persisted
  • Flow state: resolved | fallback (with reasons) | excluded; refines balances a parent flow, abstract excludes it only once a valid refinement exists
  • Interfaces inherit physical and chip boundaries along the flow's interface chain
  • leveled-analysis.ts: one parse and one effective model per DFD state, cached; every consumer — save path, validator, table groups, asset roll-up, reporter — asks there
  • Findings (leveled-findings.ts) never block editing, saving or generation: "error" only marks the DFD phase incomplete
  • Table groups (table-groups.ts): an element belongs to the top-level decomposed multiprocess it lies in, a flow to that group only if both resolved ends lie inside it
  • Asset roll-up (asset-rollup.ts): a decomposed multiprocess holds no relations of its own; its view is the distinct (asset, relation type) pairs of its parts, read-only
  • Schema 9 is the version fence: older releases refuse a file whose pages they would silently merge
