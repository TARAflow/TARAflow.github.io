Asset Model

The asset model: assets in nine groups, two kinds of relations with one write path each, and an auto-derivation engine for CIANAAA security goals.

01

AssetProperties

  • assetGroup: data | function | system | infrastructure (vertical) · process | physical | service | human | environment (orthogonal)
  • id is an opaque UUID (stable across a group change); displayId is the readable, group-prefixed label (DA-001, FU-002), regenerated on a group change
  • properties: one flat, shared AssetProperties schema; linkedDFDElements and the physical impact are derived from the DFD and the hazard model
  • Impact factors: financial, operational, regulatory, recoverability — drive initialImpact
02

CIANAAA Derivation

  • Each asset has securityGoals[]: { type: CIANAAAGoal, level: CIANAAALevel }
  • level ≠ none → goal is active → contributes to STRIDE category set via CIANAAA_TO_STRIDE
  • maxLevel() across active goals for a STRIDE category → initialImpact on threat
  • Asset-to-element sync: bidirectional — element changes propagate to asset linkedElementIds
03

Relations

  • Element → asset: stored on the DFD element or flow (assetRelations); allowed types per element type and asset group (getAllowedRelations); the relation takes its asset's group
  • Asset → asset: canonical edge list assets.relations[] (A2ARelation with own id, source, target, type and attributes such as stepOrder or degradationMode), schema 8
  • One write path for asset links: A2A operations (add / remove / update) through the relations service (applyA2AOps) — the relation dialog, the asset graph and the asset import all use it
  • Rules in shared/models/asset-a2a-rules.ts: allowed types per group pair, core types, target classes (valid / reverse-only / invalid), mirror pairs, inverse names
  • validateA2ARelations reports links the rules no longer allow; nothing is removed by validation
