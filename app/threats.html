Threats

TARAflow generates STRIDE threats automatically from your DFD. Every threat is linked to the element or interaction it originates from, to the asset it endangers, and to the mitigations and verifications that address it.

01

Generation Methods

Per Element

Element-level threats

One threat per STRIDE category per DFD element. Focuses on internal vulnerabilities: what can go wrong inside this component.

Per Interaction

Communication threats

Threats from sender and receiver perspective on each DataFlow. Focuses on communication risks: spoofing, tampering, eavesdropping on the channel.

Manual

Custom threats

Add threats that the generator cannot derive from the model — scenario-specific, compliance-driven, or expert knowledge.

Choosing a method: Per-element is efficient and well-suited for standard systems. Per-interaction gives better coverage for communication-heavy architectures (fieldbus, REST APIs, embedded buses). Both methods can be used in the same project — they populate separate tables.

03

Review Workflow

1

Generate

Click "Generate Threats" to run the generator for all DFD elements. TARAflow creates one threat per applicable STRIDE category per element, filtered by element type, technology, and protocol properties.

2

Review & Prioritize

Each generated threat has a description, cause, attack scenario, and proposed mitigations pre-filled from the catalog. Review each threat and mark it as relevant, not relevant, or deferred.

3

Link Assets

Threats are automatically linked to the assets on the source DFD element. Verify the asset links and adjust if needed — asset CIANAAA goals determine which STRIDE categories were generated.

4

Assign Mitigations

Each threat comes with catalog mitigations pre-proposed. Mitigations already reflected in DFD element properties are automatically marked as implemented. Add, remove, or replace mitigations as needed.

5

Sync after DFD changes

When the DFD changes — new elements, renamed components, moved boundaries — TARAflow detects which threats are orphaned or missing and offers a one-click sync. Manual threat assignments are preserved.

04

Domain Coverage

The threat catalog is organized by domain. TARAflow selects templates based on element type, technology, protocol, and system class — you see threats relevant to your system, not a generic flat list.

General
Process, DataStore, DataFlow, ExternalEntity — baseline STRIDE for any system.
Embedded / OT
Fieldbus protocols (Modbus, CAN, Profibus), bootloaders, RTOS tasks, firmware tampering.
Cloud
API boundaries, service-to-service, JWT/token threats, cloud-specific DoS.
Mobile
App binary tampering, repackaging, client-side storage threats.
Physical
ChipBoundary (JTAG, side-channel, Secure Boot), PhysicalBoundary (tamper, depot attacks).
Gap
Property-triggered threats: missing fail-safe state, no backup, unsigned firmware update.
