DFD Modeling

TARAflow uses draw.io as its DFD editor. Import or draw your data-flow diagram, then parametrize each element with type, technology, protocol, and security properties.

01

Element Types

Process [P-xx]

Process

Software component, service, or controller. Properties: technology (bootloader, rtos_task, driver, protocol_stack), malwareProtection, accountManagement.

DataStore [DS-xx]

DataStore

Persistent storage. Properties: technology (flash, eeprom, ram, database), encryption, backupMechanism.

DataFlow [DF-xx]

DataFlow

Communication channel. Properties: protocol, encryptionInTransit, location (field_cable, on_board), safetyFunction, accessMode.

ExternalEntity [EE-xx]

ExternalEntity

Actor outside the system boundary. Properties: entityType (human, external_system, sensor).

TrustBoundary [TB-xx]

TrustBoundary

Logical security zone boundary. Threats are generated at crossing points.

PhysicalBoundary [PB-xx]

PhysicalBoundary

Physical enclosure boundary. Properties: tamperProtection, physicalAccessControl, physicalMobility.

ChipBoundary [CB-xx]

ChipBoundary

Hardware security boundary. Properties: chipType, debugInterfaceLocked, sideChannelProtection, cryptoStandard.

Interface [IF-xx]

Interface / PhysicalInterface

Physical or logical interface port. Properties: implementedControls (logicalAccessControl, debugProtection, physicalAccessProtection, abuseProtection, monitoringControl).

02

DFD Completeness Rules

  • All system components, data flows, and trust boundaries must be present
  • All elements must be named and numbered (P-xx, DS-xx, DF-xx, EE-xx)
  • Assets and Interfaces must be placed on the correct elements
  • Consistent with architecture — version-controlled in repository
  • Re-assessment trigger when context or architecture changes
