Overview & Setup

Create a project, set the system context, choose criticality, and configure regulatory tags. These settings drive template filtering and report generation throughout the assessment.

01

Project Setup

  • Project name, version, and responsible roles
  • System description — scope and deployment context
  • Criticality: standard or critical system (affects workflow variant selection)
  • Industry tags: OT, Medical, Automotive, IoT, Cloud
  • Platform tags: Embedded, Linux, RTOS, Bare-Metal, Cloud, Mobile
  • Regulatory tags: IEC 62443, EN IEC 62443 (CRA), ISO 21434, CRA, EN 50742 — drive mitigation catalog filtering
  • Tags that change the workflow are marked: method tags (ISO 21434, EN 50742, ETSI TVRA) dark with a cog, matrix tags (IEC 62443, EN IEC 62443 (CRA)) outlined with a shield
02

Item / System Definition

  • Called Item Definition in ISO/SAE 21434 projects, System Definition everywhere else
  • Overview → Definition: purpose and functions, item boundary, preliminary architecture, operational environment and constraints — each with text, a source document and links into the DFD and the assets
  • Functions with their lifecycle phases
  • Assumptions (ASM-nn) with owner, review date and status; trust boundaries link the assumptions they rely on
  • Missing mandatory parts are reported; the report has an Item Definition chapter
03

Phase Overview

  • Every phase card explains its status and opens its tab
  • Badges on the phase tabs show open findings — including the Risk tab's, e.g. a risk to reduce without a mitigation
  • In ISO/SAE 21434 projects the status of the TARA verification shows in the Overview and the phase bar
04

Context Profile

The context profile is used throughout the assessment: platform tags filter embedded-specific threat templates; regulatory tags surface norm-relevant mitigations; criticality determines whether Variant A (STRIDE-first) or Variant B (Attack-Tree-first) is the default workflow.
