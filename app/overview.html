App / 01

Overview & Setup

Create a project, describe it and tag it. The tags select the method, the requirement matrices and whether the Hazard tab is needed; the Overview shows where every phase stands.

01

Project

  • Name, version, responsible and description — the same fields in the new-project dialog and the Overview
  • Safety Analysis switch: shows the Hazard tab; a regulation tag that mandates hazard analysis turns it on
  • Window of opportunity (EN 50742 A only): very restricted · moderately restricted · limited · unlimited — project-wide, it enters every attack potential
  • Every phase card explains its status and opens its tab; badges on the phase tabs show open findings — including the Risk tab's, e.g. a risk to reduce without a mitigation
  • In ISO/SAE 21434 projects the status of the TARA verification shows above the project data and in the phase bar
02

Tags

  • Domain: Aerospace, Automotive, Aviation, Consumer, Energy, Finance, Industrial, Medical, Military, Pharma, Public Sector, Railway, Telecom, Transportation, Water
  • Platform: Web, Mobile, Desktop, Cloud, Backend, Embedded, OT, IoT, AI
  • Regulation: CRA, NIS2, GDPR, AI Act, IEC 62443, EN IEC 62443 (CRA), EN 18031, IEC 81001, IEC TR 60601, ISO 21434, CLC/TS 50701, IEC 63452, ISO 27001, ETSI TVRA, ISO 27017, ETSI EN 303 645, EN 17927, IEC 62351, EN 50742 A
  • Custom tags without a category are possible
03

What the Tags Change

Method · cog

Regulation preset

ISO 21434, EN 50742 A and ETSI TVRA select the risk method — likelihood factors, impact aggregation, threat generators, work products and report chapters. Without one the project uses the Standard preset.

Matrix · shield

Requirement matrix

IEC 62443 and EN IEC 62443 (CRA) enable the IEC 62443-4-2 matrix in the Compliance tab and its report chapter.

Hazard

Hazard analysis

EN 50742, IEC 81001, IEC TR 60601, IEC 63452 and CLC/TS 50701 require the Hazard tab — the Safety Analysis switch follows them.

Context

Control proposals

Domain and platform gate the catalog controls: in-vehicle controls only in the Automotive domain, embedded-only controls only on an embedded platform.

04

Item / System Definition

  • Called Item Definition in ISO/SAE 21434 projects, System Definition everywhere else
  • Overview → Definition: purpose and functions, item boundary, preliminary architecture, operational environment and constraints — each with text, a source document and links into the DFD and the assets
  • Functions with their lifecycle phases
  • Assumptions (ASM-nn) with owner, review date and status; trust boundaries link the assumptions they rely on
  • Missing mandatory parts are reported; the report has an Item Definition chapter
05

Methodology and Sources

  • Overview → Methodology: the method the project applies, read-only and derived from the configuration, with the report's wording; scales, matrix and acceptance criteria are edited in the Risk tab's configuration
  • Project settings: strict validation, auto save and its interval
  • Overview → Sources: the repository and release the TARA was performed against — URL and a branch, release branch, tag or commit; Resolve checks it with git ls-remote after asking once per host
